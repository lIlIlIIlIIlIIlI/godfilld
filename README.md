# 별의 의회 · Aether Arena

갓필드의 카드 전투에서 영감을 받은 독립 HTML5 카드 배틀 게임입니다. TypeScript/Vite 클라이언트, Node.js 서버 권위형 게임 엔진, WebSocket, SQLite 개발 저장, PostgreSQL 운영 저장을 사용합니다. Flash·SWF·Ruffle은 포함하지 않습니다.

현재 버전은 **실행 가능한 개발 빌드**입니다. 원본 규칙의 완전 재현이나 공개 운영 완료 상태가 아닙니다. 검증 범위와 남은 작업은 [진행 현황](docs/progress.md)에 기록합니다.

## 이번 조사와 배포 준비 (2026-10-19)

[현행 God Field 조사 보고서](docs/godfield-research-2026-10-19.md)에 공식 HTML·한국어 JSON·나무위키·REA Evidence와 파일 해시를 정리했습니다. 공식 서버 내부 판정은 확인하지 못했으며, 기존 독립 규칙과 원작의 차이를 게임 방법 화면에서도 확인할 수 있습니다.

2~9인 훈련 선택, 9인 멀티플레이, 재대전 인원 유지, 실제 9개 소켓의 손패 분리 검사를 추가했습니다. Docker가 설치된 서버에서는 다음으로 클라이언트와 WebSocket 서버를 함께 실행합니다.

```bash
docker compose up --build -d
```

`http://localhost:3000`으로 접속합니다. SQLite는 `arena-data` 볼륨에 보존됩니다. 외부 서비스는 도메인의 HTTPS/WSS를 같은 서버로 연결하세요. 여러 인스턴스·Vercel 운영은 전용 PostgreSQL이 필요합니다. [배포·복구 지침](docs/operations.md)을 참고하세요.

GitHub Actions가 테스트·100경기·운영 빌드·Docker 이미지·실제 9인 소켓과 재접속을 검사하고 `dist` 산출물을 보관합니다. 자체 호스팅 서버에 대한 검사는 `npm run smoke -- https://서버주소`로 실행하며 임시 비공개 검사 방을 만듭니다. 실제 외부 호스팅의 신규 게시·운영 승격은 이번 변경에 포함하지 않습니다.

## 바로 실행

Node.js24, npm이 필요합니다. 별도 계정이나 게임 API키는 필요하지 않습니다.

```bash
npm ci
npm test
npm run build
npm start
```

`http://localhost:3000`에서 접속합니다. 이름을 입력하고 **탄생하기→훈련 인원(2~9명)→AI 연습 대전**을 선택하면 사람 1명과 선택한 수의 AI가 경기를 시작합니다. 기본은 4명입니다. 다른 브라우저/별도 프로필로 같은 서버에 접속하면 멀티플레이할 수 있습니다. 동일 프로필은 같은 재접속 토큰을 사용합니다. 사람마다 별도 브라우저 저장 공간을 사용해 주세요.

일반 방: 방 입장→개인전 또는 팀 버튼으로 대기열 참가→내 이름을 눌러 준비→2명 이상 모두 준비되면 방장이 시작. 방 입장만으로는 대기열에 이름이 올라가지 않습니다. 방 설정에서 대기열 참가를 취소해도 방에는 남아 있습니다. 팀전은 시작 전에 팀을 선택할 수 있습니다. 대전 후 재대전·공개 전투 기록을 볼 수 있습니다. 이름·음량·애니메이션은 설정에서 변경합니다.

연습전과 방 만들기에서 재앙 시작을1·50·100·500턴 중 고릅니다. 기본은100턴입니다. 사용자 요청에 따라 첨부 사진의 1080×720 구성과 같은 원본 홈·민트·분홍 종말 배경 및 로고를 사용합니다. 초록 상하단 바, 오른쪽 능력치, 아래 그림 손패와 일으킨 기적을 같은 위치에 배치합니다. 카드 이름·설명은 마우스 이동이나 선택으로 확인합니다. PC·가로 화면은 기존 배치를 유지하고, 폭760px 이하 세로 화면은 첨부 모바일 사진의6열 손패→플레이어 능력치→기적 버튼 배치를 사용합니다. 640px 최소 폭을 제거했으며, 카드가16장이면3번째 줄과 나머지 영역이 세로로 이어집니다. 시작·실제 피해·악마·승천·승리 표시를 서버 이벤트에 연결했습니다. 상세 내용은 [모바일 화면 기록](docs/mobile-layout.md)에 있습니다. 한국어 카드명은 신규 명칭이며 원작 번역명이 아닙니다.

전투의 초록색 시간 바는 서버의 기본60초 입력 마감까지 줄어들고,20초부터 빨간색으로 표시합니다. 카드 선택·채팅·일반 재접속으로 시간이 다시 늘지 않습니다. 시간이 끝나면 서버가 AI로 자동 진행합니다. G.F. 종말 진행도와 별개입니다. [자료 확인과 구현 기록](docs/queue-and-turn-timer.md)을 참고하세요.

마지막 사람이 방에서 나가면 방을 삭제합니다. 연결 끊김은 마지막 활동부터2분 동안 복구할 수 있으며, 그동안 다른 참가자가 있으면 AI가 대신합니다. 만료된 방은 목록 조회와 정리 주기에서 제거됩니다. 방 삭제 후 영구 경기 기록 아카이브는 제공하지 않습니다. 사진 참고 UI와 버그 수정 내역은 [UI·방 정리 기록](docs/ui-reference-notes.md)에 있습니다.

개발 중에는 두 터미널에서 다음 명령을 실행합니다.

```bash
npm run dev
npm run dev:client
```

Vite의 `/api` 프록시가 Node 서버3000에 연결됩니다. 기본 SQLite 파일은 `arena.sqlite`, 다른 경로는 `SQLITE_PATH`, 포트는 `PORT`입니다. `.env.example`을 참고하되 실행 환경에서 변수를 직접 설정하거나 `node --env-file=.env --import tsx server/src/index.ts`로 불러오세요. 자동으로 `.env`를 읽는다고 가정하지 않습니다.

## 운영 배포

Vercel 프로젝트 `aether-arena`에 배포했습니다. 최초 실행 로그의 ESM import 오류를 수정하여 `.js` 경로와 JSON import 속성을 추가했습니다. 수정 커밋 `88b0339`의 Preview 배포는 READY이며 인증 후 `/api/health`200(`PostgresStore`)과 `/api/rooms`200을 확인했습니다. DB 환경 변수도 설정된 상태입니다. 실제 운영 WebSocket 대전·재접속·모바일 검증과 로그인 없는 공개 접근 검증은 아직 남아 있습니다. Vercel에서는 SQLite로 조용히 대체하지 않고 DB 설정 오류로 중단하도록 했습니다. 운영 설정·시크릿은 저장소에 넣지 않습니다.

소스 저장소는 [lIlIlIIlIIlIIlI/godfilld](https://github.com/lIlIlIIlIIlIIlI/godfilld)입니다. Vercel에서 이 저장소의 커밋을 배포했으며 루트 디렉터리는 저장소 루트입니다. 전체 운영 검증 범위는 operations.md를 참고하세요.

## 라이선스와 리소스

AGPL-3.0-only. 참고 데이터의 출처와 고정 커밋은 `data/provenance.json`, 고지는 `NOTICE`, 라이선스 본문은 `LICENSE`에 있습니다. 교전 안의 소스 코드 링크는 빌드 시 생성한 `/source.zip`을 제공합니다. 수정 배포할 때 해당 배포에 대응하는 소스를 다시 빌드해 함께 제공해야 합니다.

사용자가 원본 이미지·사운드 사용 허가를 받았다고 확인하여 원본 그림과 MP3를 포함했습니다. 일반 드로우244종 전부를 포함한246개 카드 ID를 원본 표시 데이터에 따라 매핑했고, 그림317개를 개별 무손실 WebP 파일로 최적화했습니다. 원본 효과음46개와 이벤트 대응표, 권한 확인 근거·원본 해시·미보유118개 역사 카드 목록은 [자산 감사](docs/asset-audit.md)에 기록했습니다. 이미지는 손패·도감·상세에서 표시하며, 첫 터치 이후 효과음을 재생합니다. 배경 음악은 별도 합성 음원입니다. 원본 미디어는 코드의 AGPL과 별개이며 SWF·Flash 실행 엔진은 포함하지 않습니다.
