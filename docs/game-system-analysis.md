## 전투 흐름을 따라간 결과

`Session.COMMAND → TurnHandler.attackerCommand → queueAttack → Room.nextInning/endInning → doAttack → defenderCommand → inflictDamage`로 이어집니다. 반사·튕김은 currentAttack의 공격자·대상을 바꾸고 방어를 다시 요청합니다. COUNTER는 피해 감소 뒤 남은 공격량을 별도 공격으로 큐에 넣습니다. 광역은 살아 있는 적마다 AttackData를 복제하며 명중을 각자 판정합니다. 원래 공격자 자신의 질병 효과는 큐를 모두 처리한 다음, 적 수호자의 30% 개입보다 먼저 처리됩니다.

### 카드 지급·기적

Player.reset의 `deal=10`은 즉시 지급이 아닙니다. startGame→nextInning→endInning→doPlayersDeals에서 첫 공격자 선정 전에 지급합니다. 일반 카드 사용·영구 기적 사용 모두 `deal += 1`을 예약하고, 행동의 연쇄가 끝난 뒤 살아 있는 플레이어에게 보충합니다. 버리기는 별도 경로이므로 단순 사용처럼 보충되지 않습니다. `MAGIC` 첫 사용은 손패에서 제거해 magics에 ID를 더하고 이후 MP로 재사용합니다. 코드의 16장 검사는 pieces만 보며 magics는 세지 않습니다. 블로그의 영구 공간 설명과 같다고 취급할 수 없습니다.

### 조합과 속성

첫 카드로 방어구는 거부됩니다. MAGIC/SUNDRY는 attackKind가 있어야 시작할 수 있습니다. 후속 카드는 확률이 없는 WEAPON으로 시작한 경우 INCREASE_ATK/DOUBLE_ATK/WIDE_ATK/ADD_ATTRIBUTE를 허용합니다. MAGIC_FREE는 바로 앞의 기적 비용을 면제하는 용도입니다. 광역·배율 기적 단독 사용은 유효하지 않습니다.

INCREASE_ATK는 종류에 맞는 value 또는 subValue를 더합니다. ADD_ATTRIBUTE는 후속 위치에서 속성을 덮어쓰지만 그 카드의 기본 공격 수치를 추가로 더하지 않습니다. 첫 위치에서는 자신의 기본 공격을 냅니다. 속성 혼합은 먼저 LIGHT라면 후속 속성으로 바꾸고, 서로 다른 일반 속성은 무속성으로 합쳐지며 후속 LIGHT는 기존 속성을 유지합니다. WIDE_ATK는 무속성 전체 공격으로 바꿉니다.

| 공격                             | 코드에서 허용한 일반 방어 속성          |
| -------------------------------- | --------------------------------------- |
| 무속성·어둠                      | 모든 속성                               |
| FIRE                             | WATER, LIGHT                            |
| WATER                            | FIRE, LIGHT                             |
| TREE                             | SOIL, LIGHT                             |
| SOIL                             | TREE, LIGHT                             |
| LIGHT                            | DARK                                    |
| 속성이 없는 거래·특수 입력(null) | 일반 방어 불가, 적합한 특수 방어는 별도 |

특수 방어는 무기/기적 분류와 COUNTER 여부도 봅니다. REFLECT_ANY는 넓은 예외입니다. 일반 방어는 합성된 방어 속성과 공격 속성을 검사한 후 감소한 피해를 적용합니다. 195는 속성 제거, 196은 만능 반사, 187/190은 피해 기준 공격 반격, 193은 두 배 MP, 194는 소지금 흡수입니다.

### 거래·사망

강매는 판매자 손패의 두 번째 카드가 실제로 존재해야 하며, 카드 가격을 상대에게 청구합니다. `decreaseYen`은 잔액이 모자라면 MP, 다음 HP를 차감합니다. BUY는 상대 손패 무작위 1장을 고른 뒤 구매자의 응답을 기다리며, 구매자의 소지금만으로 가격을 감당해야 합니다. 부족분 환산은 강매와 소지금 흡수에 쓰이고 자발적 구매에는 적용하지 않습니다.

HP0은 Room.handlePlayersDeath에서 검사합니다. 244 부활을 먼저 시도하고, 없으면 dead를 설정하고 117 유언 공격을 큐에 추가합니다. 큐가 남아 있으면 최종 종료를 미뤄 후속 공격을 처리합니다. 원본은 생존자 수에 따른 추가 조건이 있으며 새 게임에서는 남은 사망 효과를 끝까지 처리하는 정책을 명시했습니다.

### 재앙·수호자·운명

질병 피해는 1/2/5, 천국병은 회복5입니다. 코드의 악화 확률은 worseChance를 0으로 시작해 실패할 때마다 1 증가시키고 악화 시 초기화합니다. 블로그의 턴당 고정5%와 다릅니다. addHarm은 기존 단계보다 강한 질병이면 해당 단계로 이동하고, 같거나 약하면 기존 단계에서 하나 악화시킵니다.

꿈은 드로우 때 거래/기적을 제외한 카드의 50%에 유사 카드 표시를 덧씌우며 실제 효과는 원래 카드입니다. 안개는 아군/적군 대상군 안에서 재지정하지만 정보 은폐가 불완전하다는 README 경고가 있습니다. 섬광은 봇 방어에 제한 코드가 있으나 모든 인간 명령에 대한 안전한 강제가 아닙니다. 먹구름은 확률형 명중 실패를 무시합니다.

수호자는 주인의 피해를 선흡수하고 HP가 남지 않으면 삭제됩니다. 적의 행동 끝에 30% 개입합니다. EARTH는 일반 드로우 결과를 공격/거래/선물로 이용하고 MOON은 기적을 고릅니다. `AssistantItemData.CSV`의 ID는 원본에서 종류마다 다시 0부터 매겨집니다. 본 프로젝트의 summon JSON id는 CSV 전체 행 번호이며 종류별 매핑은 card-reference에 별도 표기했습니다.

MYSTERY는 MARS 열병, MERCURY 안개, JUPITER 꿈, SATURN 모두 HP1, URANUS 무작위 빛60, PLUTO 적 전체 어둠30/75%, NEPTUNE 본인 회복60, VENUS 모두 소지금99, EARTH 손패 재분배, MOON 모두 무작위 수호자의 10분기입니다. 새 엔진에서 개별 레지스트리 함수로 분리했습니다.

### 종말의 확인 한계

블로그에는 턴 진행에 따른 G.F.와 종말 이후 카드 사용·지급 시25% 악마 위험이 설명되어 있습니다. 서버 파일의 실제 제어 흐름에서는 G.F.·종말·악마 생성을 찾지 못했습니다. weight0 CREATURE 8행은 존재하지만 ItemManager의 일반 드로우로 선택되지 않고, 종말 이벤트에서 이를 호출하는 경로도 확인하지 못했습니다. 따라서 시작 턴·악마 피해·연쇄 규칙을 원본 확정값으로 제시할 근거가 없습니다. 새 게임의 설정임을 Rules.ts와 도움말에 표시했습니다.

## 새 구조와 검증의 한계

TypeScript 순수 상태 변환 엔진과 명시적 단계, 직렬 공격 큐, 실패 시 롤백, 서버 카드 인스턴스 UID, 비공개 투영, 결정적 난수, 명령 기록을 새로 설계했습니다. 파이썬 서버 실행·XML 프로토콜·Flash 런타임을 복사해 사용하지 않습니다. 카드 수치는 AGPL 참고 데이터의 ID 대응을 유지합니다.

테스트 통과는 이 명세에 대한 검증입니다. 원작과 전체 카드 동작이 완전히 같다는 증명, 브라우저 실사용 검수, PostgreSQL·Vercel 실서비스 검증을 대신하지 않습니다. 원작 공식 수치, Flash 내부 이름·리소스 매핑, 장시간 대규모 부하와 프로덕션 복구는 추가 검증 대상입니다.
