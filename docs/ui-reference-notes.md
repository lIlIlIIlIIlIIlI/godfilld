# 첨부 사진 그대로의 화면 구성으로 수정

2026-10-18. 사용자 첨부 사진 5장을 실제로 열어 확인했습니다. 앞선 구현의 새 이름·패널 재배치·합성 구름 배경은 사용자의 요청과 달랐습니다. 해당 디자인을 제거하고 사진의 1080×720 화면 구성으로 바꿨습니다. 첨부 사진 자체를 잘라 배포하는 방식은 사용하지 않습니다.

| 사진 | 현재 적용 |
| --- | --- |
| 첫 번째 | 같은 원본 로고·홈 배경·앱 배지, 이름 입력, 탄생하기, 초록 상하단 바 |
| 두 번째 | 같은 원본 민트 배경, 개인전/팀전 도형, 가운데 참가자 슬롯, 종말 시간, 하단 게시 입력 |
| 세 번째 | 같은 원본 분홍 종말 배경, 검은 G.F. 표시, 기도하기, 그림 손패 |
| 네 번째·다섯 번째 | 공격자→대상, 오른쪽 가로 능력치, 중앙 카드 설명, 하단 80×80 손패, 오른쪽 일으킨 기적·카드 설명 |

## 화면과 원본 파일

client/public/assets/reference/의 홈·방·종말 배경, 로고와 앱 배지 6개는 공식 사이트의 대응 파일과 바이트가 같습니다. 파일 URL·SHA256·크기는 data/ui-asset-manifest.json에 기록했습니다. 사용자가 확인한 사용 허가를 근거로 포함하며 독립적인 권리 문서를 확인했다고 주장하지 않습니다. 원작 앱 배지는 원작 스토어 주소로 연결하고 접근성 이름에도 원작임을 명시합니다. 이 프로젝트의 앱이 있다고 표시하지 않습니다.

원본 기준 화면은 1080×720, 상단 30·본문 660·하단 30입니다. 홈 로고는 본문 (240,90), 이름은 (350,340), 탄생하기는 (300,400)입니다. 전투 플레이어는 (680,94), 손패는 (10,454), 기적 버튼은 (770,360)에 배치했습니다. 80×80 손패는 9열이며 보유 카드가 더 많으면 다음 줄에 실제 카드를 표시합니다. 카드 이름은 마우스 이동·선택 시 중앙과 오른쪽 설명에 표시하며 스크린리더 이름도 유지합니다. 사진의 카드 이름을 무관한 카드 ID에 임의로 붙이지 않습니다. 한국어 카드명은 기존 신규 명칭입니다.

추가로 받은 모바일 사진8장에 따라 폭760px 이하 세로 화면은6열 손패→능력치→기적 버튼으로 배치합니다. 640px 최소 폭과 가로 스크롤 설정은 제거했습니다. PC·가로 화면은 기존 배치를 유지합니다. [모바일 구현 및 검사 범위](mobile-layout.md)를 참고하세요. 휴대폰 실기기 검수는 미실시입니다.

## 실제 조작 연결

- 이름 입력→탄생하기 후 훈련·결투 메뉴에서 실제 연습전이나 방에 진입합니다.
- 대기실의 내 슬롯은 준비를 전환합니다. 하단 이름이나 종말 시간을 누르면 봇·초대·준비·시작·종말 1/50/100/500 설정을 엽니다.
- 개인전/팀 도형은 서버 명령입니다. 모드 변경과 종말 설정은 방장만 가능하며 진행 중 변경을 거부합니다.
- 사진의 기도하기는 서버의 턴 넘기기, 용서하기는 방어 없이 피해 받기로 연결합니다. 카드를 고르면 사용하기/방어하기로 바뀝니다.
- 카드 더미 메뉴에서 필터·선택 해제·버리기를 사용합니다. 일으킨 기적 버튼은 실제 영구 기적 목록을 엽니다.
- 전투 하단 이름으로 기록·채팅을 열고, 음량 막대로 설정을 엽니다. 교전 안에서 대응 소스 ZIP을 내려받습니다.
- 종말은 서버 진행도 100에서 표시하고 악마 알림은 실제 서버 이벤트만 사용합니다.

battle.ts는 서버 GameView와 로컬 선택 상태를 받아 HTML을 만드는 렌더러입니다. 게임 판정은 기존 서버 엔진에 유지합니다. Flash·SWF·Ruffle 및 원본 클라이언트 프로그램은 실행·배포하지 않습니다.

## 빈 방 버그

기존에는 퇴장 시 좌석만 지우거나 AI로 전환했고, SQLite/PostgreSQL 방 레코드에는 삭제 경로가 없었습니다. 그 결과 빈 대기실과 사람 없는 연습전이 계속 남았습니다. 회귀 검사에서 수정 전 6건 중 5건이 실패하는 것을 확인했습니다.

- 마지막 사람이 명시적으로 퇴장하면 봇·관전자 유무와 관계없이 방을 삭제합니다.
- 다른 사람이 남은 진행 경기는 퇴장한 좌석을 AI가 조작하고 방장을 남은 사람에게 넘깁니다.
- 연결이 끊긴 경우 마지막 활동부터 120초 동안 복귀할 수 있습니다. 활성 연결은 클라이언트 heartbeat와 WebSocket pong으로 갱신합니다.
- 목록 조회·서버 정리 주기에서 만료된 방을 정리합니다. 대기실의 오래된 좌석은 제거하고, 진행 경기의 일부 연결 끊김은 남은 사람의 경기를 중단하지 않습니다.
- 삭제 조건을 DB 잠금 안에서 다시 확인하여 정리 도중 재접속한 방을 지우지 않습니다. 삭제도 기존 변경 트랜잭션 안에서 수행합니다.
- 로비에 목록을 다시 보내고 관전자에게 `room_closed`를 전달합니다. 클라이언트는 방 화면·저장된 방 ID·카드 선택을 정리합니다. 이미 만료된 방의 재접속 오류도 같은 흐름으로 복구합니다.

방 기록은 방이 존재하는 동안 열람할 수 있습니다. 방을 삭제한 뒤 영구 경기 기록을 제공하는 별도 아카이브는 없습니다.

## 확인 범위

전체 자동 검사 381개가 통과했습니다. 새 검사에는 마지막 퇴장, 봇만 남은 방, 방장 이전, 2분 유예, 오래된 저장 방, 정리/재접속 경합, PostgreSQL 트랜잭션 삭제/롤백, 만료된 방의 클라이언트 복구가 포함됩니다. 실제 로컬 WebSocket 검사에서는 참가자·관전자에게 방 종료와 빈 목록이 전파되고 HTTP 목록에서도 제거되는 것을 확인했습니다. DOM 검사로 전투 영역·카드 선택·종말 전환·실제 악마 이벤트·종료 화면 복구를 확인했습니다.

실브라우저 스크린샷, 휴대폰 터치 및 스피커 청취는 이 환경에서 미실시입니다. 반응형 구현과 자동 검사 통과를 실기기 검증으로 표시하지 않습니다.
