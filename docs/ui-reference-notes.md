# 사진 참고 UI 및 방 정리 수정

2026-10-18. 사용자가 보낸 사진 5장을 실제로 열어 확인했습니다. 첨부 사진 자체를 게임 자산으로 배포하지 않고, 색상·정보 배치·상태 표현을 HTML/CSS로 구현했습니다.

| 사진 | 참고한 요소 | 적용 |
| --- | --- | --- |
| 첫 번째 | 연두색 진입 화면, 큰 제목, 초록색 상·하단 | 새 게임명, 플레이어 이름, 연습/멀티플레이, 실제 음량 표시 |
| 두 번째 | 민트색 대기 화면, 둥근 참가자 슬롯, 종말 시간 | 팀 도형, 빈 좌석, 준비·봇·초대·시작, 선택된 종말 시간 |
| 세 번째 | 종말의 분홍 구름과 검은 G.F. 표시 | 서버 진행도 100에서 배경·G.F. 색상 변경 |
| 네 번째·다섯 번째 | 공격자→대상, 가로형 능력치, 큰 카드 그림, 기적 영역 | 전투 카드/손패는 왼쪽, 플레이어/기적은 오른쪽 |

`client/src/battle.ts`는 서버 `GameView`와 UI 선택 상태를 받아 HTML을 만드는 렌더러입니다. 판정 로직을 포함하지 않습니다. `field.css`가 참고 화면의 테마·배치를 담당하고 `field-clouds.svg`는 코드로 작성한 구름 배경입니다. 카드 이름·그림·수치와 별도 상세 버튼을 유지합니다. 기록·채팅은 버튼으로 펼칠 수 있습니다. 작은 화면에서는 플레이어 2열·손패 4열, 손패 내부 스크롤, 하단 고정 행동 버튼을 사용합니다. 기존 원본 이미지·효과음 연결도 유지합니다.

종말은 `GameView.doom >= 100`에서만 표시합니다. 악마 출현 알림은 서버의 실제 `demon` 이벤트와 대상·피해량을 사용하며 임의의 결과를 만들지 않습니다. 경기 종료 뒤 새 악마 이벤트를 생성하지 않는 엔진 규칙은 그대로입니다.

## 빈 방 버그

기존에는 퇴장 시 좌석만 지우거나 AI로 전환했고, SQLite/PostgreSQL 방 레코드에는 삭제 경로가 없었습니다. 그 결과 빈 대기실과 사람 없는 연습전이 계속 남았습니다. 회귀 검사에서 수정 전 6건 중 5건이 실패하는 것을 확인했습니다.

- 마지막 사람이 명시적으로 퇴장하면 봇·관전자 유무와 관계없이 방을 삭제합니다.
- 다른 사람이 남은 진행 경기는 퇴장한 좌석을 AI가 조작하고 방장을 남은 사람에게 넘깁니다.
- 연결이 끊긴 경우 마지막 활동부터 120초 동안 복귀할 수 있습니다. 활성 연결은 클라이언트 heartbeat와 WebSocket pong으로 갱신합니다.
- 목록 조회·서버 정리 주기에서 만료된 방을 정리합니다. 대기실의 오래된 좌석은 제거하고, 진행 경기의 일부 연결 끊김은 남은 사람의 경기를 중단하지 않습니다.
- 삭제 조건을 DB 잠금 안에서 다시 확인하여 정리 도중 재접속한 방을 지우지 않습니다. 삭제도 기존 변경 트랜잭션 안에서 수행합니다.
- 로비에 목록을 다시 보내고 관전자에게 `room_closed`를 전달합니다. 클라이언트는 방 화면·저장된 방 ID·카드 선택을 정리합니다. 이미 만료된 방의 재접속 오류도 같은 흐름으로 복구합니다.

방 기록은 방이 존재하는 동안 열람할 수 있습니다. 방을 삭제한 뒤 영구 경기 기록을 제공하는 별도 아카이브는 없습니다.

## 확인 범위

전체 자동 검사 371개가 통과했습니다. 새 검사에는 마지막 퇴장, 봇만 남은 방, 방장 이전, 2분 유예, 오래된 저장 방, 정리/재접속 경합, PostgreSQL 트랜잭션 삭제/롤백, 만료된 방의 클라이언트 복구가 포함됩니다. 실제 로컬 WebSocket 검사에서는 참가자·관전자에게 방 종료와 빈 목록이 전파되고 HTTP 목록에서도 제거되는 것을 확인했습니다. DOM 검사로 전투 영역·카드 선택·종말 전환·실제 악마 이벤트·종료 화면 복구를 확인했습니다.

실브라우저 스크린샷, 휴대폰 터치 및 스피커 청취는 이 환경에서 미실시입니다. 반응형 구현과 자동 검사 통과를 실기기 검증으로 표시하지 않습니다.
