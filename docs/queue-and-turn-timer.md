# 방 입장·대기열 참가 및 입력 시간 바

2026-10-18. 사용자 첨부 image(5).png의 긴 초록 바를 실제로 열어 확인했습니다. 이전 구현에서 이 바를 장식용 구분선으로 만든 것은 잘못된 해석이었습니다.

## 자료를 실제로 확인한 내용

- [블로그](https://subculturer-home.tistory.com/entry/무료게임-이게-왜-맞아-갓필드-게임-소개-게임-방법-사이트-링크-GOD-FIELD)의 본문은 무작위 손패로 공격/방어하고 최후 생존자가 승리하며, G.F.가 턴에 따라 증가해 종말에 들어가면 카드 사용·지급마다25% 악마 위험이 생긴다고 설명합니다. G.F.는 초 단위 입력 시간과 다릅니다. 본문에는 대기열 입장 절차나 턴 제한 초 수가 명시되지 않습니다.
- 참고 저장소 session.py의 enterHandler는 room.addUser만 호출합니다. enterGameHandler가 별도로 ENTER_GAME의 team을 받아 room.enterGame을 호출합니다. exitGameHandler도 방 퇴장과 별도입니다.
- room.py의 enterGame은 처음 참가한 사람의 SINGLE/팀 여부로 대기열 종류를 결정하고, 이후 다른 종류 혼합을 거부합니다. 기존 참가자는 팀만 변경하고, 새 참가자는 players에 추가합니다.
- 같은 참고 서버의 playerReady는2명 이상 모두 준비되면 자동으로 startGame을 호출합니다. 신규 게임은 기존 방장 시작 기능을 유지합니다. 자동 시작까지 완전 재현했다고 주장하지 않습니다.
- 공식 godfield.net의 실제 main.dart.js에서 시간 바 hw/m1 처리를 읽었습니다. private 모드는60초,40초 경과 후 빨간색으로 전환하고 끝나면 방 이탈/새로고침으로 이어집니다. duel 모드는15초/10초입니다. 이 모드 이름은 상수 정의로 확인했습니다. 이 숫자를 블로그 설명으로 인용하지 않습니다.

## 채택한 동작

일반 방은 생성/입장 시 visitors에 들어가고 seats는 비어 있습니다. 개인전 또는 팀 선택을 서버가 검증한 뒤 seats에 이동합니다. 취소하면 visitors로 돌아옵니다. 같은 선택을 반복해도 중복 좌석을 만들지 않습니다. 준비는 참가 후에만 가능하고 팀 변경 시 준비를 해제합니다. 실제 대기열 정원은2~8명이며 단순 방 입장자 수와 구분합니다.

첫 참가자가 개인전/팀전 종류를 정합니다. 다른 종류로 바꾸려면 대기열을 비워야 합니다. 미참가 방장도 방 설정·봇 추가·시작 권한을 유지합니다. 경기에는 seats만 전달하고, 미참가 입장자와 관전자에게는 개인 손패를 전달하지 않습니다. AI 연습은 기존 즉시 시작을 유지합니다.

입장자도 heartbeat·재접속·2분 유예·방장 이전·빈 방 삭제 대상입니다. 기존 저장 방에 visitors가 없으면 빈 배열로 취급하고 기존 참가 좌석은 보존합니다. 진행 중 카드/시드/경기를 초기화하는 마이그레이션은 없습니다.

입력 시간은 기본60초로 채택했습니다. 마지막20초는 빨간색입니다. 별도 랭크 duel 모드를 구현하지 않았으므로15초 모드라고 표시하지 않습니다. 원본의 자동 이탈 대신 기존 요구사항에 따라 서버 AI가 대행하고 복귀 시 조작권을 회복합니다. 서버 생성 시 테스트/별도 실행 환경의 turnMs 재정의도 유지합니다.

## 시간의 권위와 표시

- 서버가 입력 단계마다 turnStartedAt, turnDurationMs, deadline을 저장합니다.
- 공격 입력 뒤 방어자의 새 마감, 구매 확인 등 다음 입력 단계의 새 마감을 부여합니다.
- 공개 응답에 serverNow를 포함합니다. 클라이언트는 기기 시계와의 차이를 보정하고 절대 deadline에서 남은 시간을 계산합니다.
- UI는100ms마다 바의 폭을 갱신하고 초 수는 올림합니다. 카드 선택·채팅·heartbeat·일반 재접속은 마감을 늘리지 않습니다.
- 다른 참가자가 퇴장해도 현재 행동자의 마감을 늘리지 않습니다. 현재 행동자가 퇴장하면 AI 대행 지연으로 전환합니다.
- 마감 이후 도착한 행동은 서버가 거부합니다. 만료 자동 진행은 DB 잠금 아래 재확인하여 한 번 처리합니다.
- 브라우저 바가0이 되었다고 서버에 임의의 턴 종료를 보내지 않습니다. 버튼만 비활성화하고 서버 응답을 기다립니다.
- 구형 저장 경기에는 기존 deadline을 보존하고 누락된 기간/시작 시각만 기본값으로 표시합니다. 다음 입력 단계부터 새 필드를 저장합니다.

## 검사 및 한계

전체 자동 검사398개, 타입 검사와 빌드를 실행했습니다. 실제 로컬 WebSocket2명/8명 검사도 입장→별도 참가→준비→시작 흐름을 사용합니다. 새 검사는 입장/참가/취소·재접속·정원 경합·준비·관측 제한·정리·실제 공격/방어 마감·늦은 입력 거부·동시 만료·서버 시각 보정·시간 바 갱신을 포함합니다.

실브라우저 스크린샷·휴대폰 터치 및 운영 환경 전체 WebSocket 경기 검수는 별도입니다. DOM/로컬 소켓 검사나 HTTP200 확인을 실제 운영 대전 검증으로 표시하지 않습니다.
